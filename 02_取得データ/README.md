# 承認済み業務データの入力場所

- `承認済み業務データ入力テンプレート_v3.xlsx`: 従来の空テンプレート。内容を保持し、P2計算には使いません。
- `承認済み業務データ入力テンプレート_v4.xlsx`: P2連携用の空テンプレート。期間ルール、mapping ID、掲載可否、前回報酬、承認ハッシュの照合項目を含み、Gitで共有可能です。
- `抽出候補_2026-10代理店32件_11月上位原本.xlsx`: 既存資料から抽出した実データ候補。会社承認済みのGit外保管先へ移動し、リポジトリには追加しないでください。

候補値は承認済み値ではありません。根拠資料・ページ／セル位置を照合し、条件対応、粗利、原価、税区分、例外、掲載可否を承認した場合に限り、承認管理へ記録します。金額の状態は`UNKNOWN`、`NOT_PUBLISHED`、`DASH`、`ZERO`、`VALUE`で区別します。金額欄が空欄のときは未確認のままとし、0円に置き換えません。未承認データから11月支払額を確定したり、配信用成果物に反映したりしてはいけません。

テンプレート・抽出候補の再生成:

```powershell
py scripts/prepare_input_workbooks.py
```

抽出候補ブックだけが既にある場合は、`py scripts/prepare_input_workbooks.py --templates-only`で空テンプレートだけを作成できます。既存出力は上書きしません。再生成の前に出力を会社承認済み保管先へ退避し、既存データを確認してください。

他のテンプレートや抽出候補に触れずP2入力テンプレートのみを生成する場合:

```powershell
py scripts/prepare_input_workbooks.py --input-template-only
```

P2では粗利原価と条件対応を`mapping_id`で結び、前回条件にも前回月のmapping IDを記録します。`承認管理.record_hash`は入力レコードの業務列から算出したSHA-256と完全一致する必要があります。承認状態、承認者、承認日時、根拠資料／位置もレコードと承認管理の両方で照合します。例外規則種別は`DISPLAY_POLICY`、`PAYMENT_PROHIBITED`、`MANDATORY_DISCLOSURE`、`HOLD`のみ計算器が扱い、それ以外は保留します。

実際の報酬・原価データ、承認記録、原本ファイルはGitへコミットしないでください。
