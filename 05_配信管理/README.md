# 代理店別の配信管理

`配信管理入力テンプレート_架空サンプル_v3.xlsx`は、送付先マスター、本文テンプレート、月次承認、送信履歴、承認失効ルールのスキーマ確認用です。サンプルの会社・宛先はすべて架空で、送信に使用できません。

実際の送付先・宛名・TO/CC/BCC・送信元・本文・承認記録・送信履歴は、会社が指定する承認済みのGit外保管先で管理します。保管先が未指定の場合、実データをこのフォルダーやGitへ置かないでください。Zoho OAuthトークン等の秘密情報もファイルやGitへ保存しません。

送付先・宛名・送信元・本文・テンプレート・条件マスター・対象期間・添付のいずれかが変わった場合は承認を失効させ、再検証と再承認を要求します。同一`batch_id + agency_id + artifact_hashes`の冪等性キーによる重複送信を禁止します。送信結果が不明な場合は履歴照会を先に行い、盲目的に再送しません。

P5はこのブックの送付先マスターと本文テンプレートを読み込み、対象月に有効な承認状態、テンプレート内容ハッシュ、許可プレースホルダーを検証します。月次承認表にはP2入力、帳票候補、代理店別宛先、本文、テンプレートの各ハッシュを記録し、QA/承認後に一致を再検証して配布版を昇格します。実Zoho API、実宛先・実帳票、実トークンを使った検証は未実施です。P4-Aで確認済みの`ZohoMail.accounts.READ`権限だけでは下書き作成できるとみなさず、`ZohoMail.messages.CREATE`等の権限と会社の明示承認が必要です。

P3内部確認用帳票を編集して警告だけを消すことはありません。P5はP2構造化結果から承認候補を新規生成します。候補は会社承認済みGit外の制限されたQA領域に保管し、承認前に配布版として使えません。承認後に同一バイト列を配布先へ昇格します。`reply_to_address`は現在未対応で、値がある場合は処理を停止します。下書き実行履歴はGit外の会社承認済みDBに保存し、同一代理店・対象月の再作成を拒否します。下書きPOST後に結果が不明な場合は自動再試行せず、Zoho上の状態を人間が確認してください。メール送信機能はありません。
